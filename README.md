# LifeCycle Hub

这是 Codex Sites 的 Worker 和 D1 源码。运行 `node build.mjs` 构建站点，运行 `node --test smoke.test.mjs` 在内存 SQLite 上验证 Worker 请求与迁移。

## 食品模块

- `FoodItem` 保存名称、品牌、分类、默认规格、储存说明、图片链接和备注。`FoodCategory` 支持内置分类与自定义子分类。
- 一条统一 `Item` 对应一个 `FoodDetail` 批次。批次连接食品档案与 `StorageLocation`，独立保存购买日期、包装标注日期、位置、保存条件、包装状态、采购量和剩余量。
- `LifecycleEvent` 保存批次的入库、开封、移动、数量调整、消耗等记录。`FoodInspection` 保存每次检查日期和备注。并发写入用批次版本校验和 D1 原子批处理。
- 食品有效期提前量和检查周期可以同时启用。食品提醒在食品页和总览实时计算，包装标注日期与用户设定的检查日各自保留。其他分类继续通过现有提醒规则和通知渲染。
- 旧食品记录保留批次地址、数量和历史事件。现有演示记录绑定其示例位置，其他旧批次先分配至「待归位」，可从批次页移动。
- 文字录入使用规则逐条提取，并以可编辑确认卡显示。确认后才一次性创建批次。相对日期按上海时区计算。

食品首页提供优先处理、位置、库存筛选和周期检查。其他页面用于管理基础档案、分类、储存位置和批次操作。第一阶段包含基础转移、冷冻和解冻事件，完整加工与分装子批次、日历、拍照和语音识别留待后续。

## V1.1 快速记录

- 食品首页新增到期日历和快速记录入口。手动添加批次先选择食品档案，选「新建食品档案」才展开档案资料。
- `intake-provider.mjs` 在服务端调用 OpenAI Responses API 处理照片和文字，并通过 Audio Transcriptions API 转写录音。语音转写后的文字与直接文字使用同一提取流程。上传的图像和录音不写入 D1。
- Site 服务端环境变量 `OPENAI_API_KEY` 启用模型。可选 `OPENAI_FOOD_MODEL` 和 `OPENAI_TRANSCRIBE_MODEL`，默认分别采用 `gpt-5.4-mini`、`gpt-transcribe`。无密钥时，文字使用规则提取，手动录入仍可用。
- `intake.mjs` 负责确认卡、保守匹配和批次操作。按名称、品牌、规格的精确匹配才能自动选档；相似档案供用户确认。多地点采购可生成多个批次并共用档案。
- `0003_food_intake.sql` 给食品批次新增本地购买时间、时区和字段来源，实际创建时间仍由 `Item.createdAt` 保存。新增临时确认草稿及确认回执，确认卡 30 分钟有效，旧草稿会在下次提取时清理。
- 验收测试用本地 SQLite 跑 Worker，并拦截外部请求来验证图片、音频和结构化提取接口的数据流。需配置密钥后用实际包装照片和录音进行线上识别验收。

## F-11 与 F-12

- `food-dates.mjs` 在语音转写和文字提取后处理原文中的确定日期、相对日期和独立的保质期天数。相对日期使用录入地的日历日期。缺少年份时预填当前年份并要求核对，有歧义时保留待确认提示。
- `0004_food_dates.sql` 增加保质期天数、计算起点和到期来源。时长在没有起点时仍可保存。明确日期经确认后写入现有批次到期字段，沿用现有提醒和日历查询。
- 批次详情提供「编辑批次」页面。表单版本用于阻止覆盖刚修改的数据。日期变更后提醒从该批次当前日期重新计算，其他批次沿用各自的数据。

## F-13

- 一段采购描述包含后续消耗时，确认卡绑定到本次新批次。规则提取与模型提取共用该确认流程。
- `0005_food_compound.sql` 增加消耗前库存量和单位。购买量、消耗前库存和剩余量分别保存。消耗历史追加至新批次，同一批写入创建操作、确认回执和消耗事件。
- 消耗前数量与消耗量必须采用同一单位。重量与个数同时出现时可以分别保存，无法确定个数时由用户补充。

## 药品 M1

- `DrugItem` 存档案，`DrugBatch` 与统一的 `Item` 一对一，并关联药品档案和 `DrugStorageLocation`。按登录主体隔离档案、成分、位置、批次、草稿和首页提醒，保留家庭归属字段。现有私有站点首次由所有者访问药品数据时绑定旧记录。
- `DrugIngredient` 与 `ActiveIngredient` 保存多个经用户核对的成分，保留包装原名、含量、计量基准及来源。名称规范化仅处理字符形式、大小写和空白。同成分库存提示只比较保存的名称，盐型不合并。
- `LifecycleEvent` 按批次保存库存变化；包装有效期、开封后使用期限和库存阈值由现有站内看板展示。开封后期限由用户按包装或说明书填写。
- `drug-intake.mjs` 复用媒体表单、音频转写、结构化提取、确认草稿和重复提交保护。无 `OPENAI_API_KEY` 时可使用规则文字提取或手动录入，拍照和语音需要配置密钥后验收。
- M1 不包含用药计划、实际服用记录、家庭共享、剂量与相互作用检查。药品提醒仅显示在需要登录的站内页面。

## 药品 M2

- `drug-plan.mjs` 提供用药计划、实际服用记录及站内提醒。计划按用户输入的来源、次数、进餐关系、时区和提醒时刻保存。缺少具体时刻时保留计划信息，用户可稍后填写。
- `0007_drug_m2.sql` 将计划和记录分表。记录保留计划时间、实际时间、状态、批次及已经应用到库存的量。计划改动不覆盖历史记录。
- 重复提交及重复计划时间由数据库约束阻止。只有确认服用且单位一致时，服用记录、库存与批次事件才在同一事务中更新。选择「仅记录服用」时库存留待核对，修改已扣减的记录时只应用差额。
- 规则和模型快速录入均区分包装内数量和用药计划。识别到计划候选时用户可以只保存入库，或勾选同时保存计划。缺失的单次剂量和时刻留空。
- 提醒显示在站内。剂量合规、相互作用、家庭共享以及站外通知留待后续。

## 药品 M3

- `drug-safety.mjs` 区分库存重叠、已服用记录及当前计划组合。服用记录保存当时的成分原名、含量与来源快照。历史无快照时提示信息不足。
- 内置两条说明书支持的有限组合规则，页面显示 DailyMed 来源和对应条款。只按列明的具体成分名称匹配，不按库存分类推断。未覆盖的组合没有核对结论。
- `MedicationSafetyRule` 保存用户从适用处方或说明书核对的上限、单位、生效日与时区。界面分别核对计划与实际记录的单次剂量、日总量、次数和间隔。时区或单位不兼容时显示信息不足。药品关键身份或成分发生变化时，已有核对规则暂停并需重新确认。
- `0008_drug_m3.sql` 新增个人核对规则和服用记录快照。所有提示留在私有站内。家庭共享与统计留待 M4。

## 食品分装与消耗统计

- `food-portions.mjs` 提供来源批次到子批次的分装。每次可创建一到三份，沿用同一个食品档案和计量单位。各份可设置位置、储存条件和冷冻记录，原批次同时扣减。
- 分装沿用原购买、生产、到期、开封和检查基准。全部分装的原批次保留在历史里，可通过关联查看各份库存。分装操作不进入消耗统计。
- `0009_food_portions.sql` 新增来源关联、继承的检查基准和结构化库存变动表。消耗、丢弃及快速录入中的实际消耗按所选日期和原单位展示。无法量化的操作单独计数。统计从部署后的结构化记录开始，旧事件保留在批次历史。

## 独立课程演示站

使用 Node.js 24。在本地运行 node build.mjs 后，以 node standalone.mjs 启动。
设置 DEMO_PUBLIC_ORIGIN 为实际入口，例如 https://demo.example.org。仅本机开发可使用
http://localhost:8080。公开部署通过 HTTPS 反向代理接入，使用单个应用进程和持久化磁盘。
直接运行默认监听 127.0.0.1:8080，数据库默认写入被 Git 忽略的 local-data/。
Docker 构建使用本目录的 Dockerfile，将持久卷挂载到 /data，确保容器用户 UID 1000
能够写入，并由 HTTPS 代理转发至容器的 8080 端口。应用目前以直接连接的地址限速，
通过反向代理访问时访客共享代理侧的 IP 限额。

DEMO_INVITATION_HASHES 接收空格分隔的 SHA-256 十六进制摘要，通过运行环境设置。
每个邀请码只能开户一次。使用 Node.js 的 crypto.randomBytes(24).toString("base64url")
生成邀请码，并用 crypto.createHash("sha256").update(code).digest("hex") 生成摘要。
只把邀请码交给拟授权访客，仓库不保存邀请码。示例站首次登录会按账号初始化虚构演示数据。

独立站使用全新的 SQLite 文件。现有 Sites 托管库、个人站资料和账号不随构建导入。
切换入口前，用目标地区的手机流量和校园网做无代理浏览器测试，验证开户、登录、批次操作、
双账号隔离和设备同步。备份时使用 SQLite 的在线备份接口，或在应用停止后备份数据目录。

## Windows 本地个人版

安装 Node.js 24 后，双击 start-local.cmd，再打开 http://127.0.0.1:8080。
按 Ctrl+C 停止服务。关闭浏览器不会删除数据。个人版无需注册，也不会导入示例库存。
数据默认保存在 %LOCALAPPDATA%\LifeCycleHub\data\personal.sqlite。
本地模式仅监听 127.0.0.1，只接受同一地址的 Host 和同源写请求。
PORT 可用于指定其他端口，LIFECYCLE_DB_PATH 仅用于选择另一份本地数据库。
如需复制整个数据目录，请先停止服务。跨平台附件备份与恢复将在后续单独提供。
